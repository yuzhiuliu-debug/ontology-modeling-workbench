# 本体建模工作台

将用户上传的表结构、业务描述和数据转换为可审阅的业务理解稿、OWL 本体、交互图谱与实例产物。AI 负责语义提案，OWL/XML、Turtle、图谱和规则 SQL 由程序生成；用户确认理解稿后再编译。

本项目面向本机单人使用。首次启动没有项目，没有预置服务商、模型地址、模型名或密钥；发布包不含业务数据、示例本体和预制业务规则。

## 启动

安装 [Node.js](https://nodejs.org/) 22 或更新版本，在项目目录执行：

```sh
node server.mjs
```

在浏览器打开终端打印的地址，默认是 `http://127.0.0.1:4188/`。端口占用时会顺延。按 Ctrl+C 停止服务。Windows 和 macOS 也可以使用项目内的启动脚本。无需安装 npm 依赖。

只查看现有 OWL 文件时，可以直接在浏览器打开 `零安装速览/速览_OWL图谱查看器.html`。

## 使用

1. 上传自己有权处理的字段字典、SQL 建表语句、Excel、CSV 或业务描述；也可导入已有本体。
2. 在理解稿中手工填写表的含义、角色和业务关系；需要 AI 时，先自行配置模型。
3. 审阅草稿图谱，修改、删除或补充关系，确认理解稿后生成 OWL。
4. 导出本体、图谱及校验报告；需要实例时再上传相应数据。
5. 规则语义解析需要可用模型；生成的 SQL 交给外部执行环境评审和使用。

详细步骤见 [使用说明](docs/USER_GUIDE.md)。规则命中或关联异常只表示待核查线索，不能直接当作违规结论。

## 模型配置与数据去向

平台支持兼容 `chat/completions` 的 HTTPS 服务。服务商、地址、模型名和密钥由使用者自行填写。自定义接口需勾选允许自定义地址。图片识别使用同一个已配置模型，请自行确认该模型支持图片输入；项目不提供模型、额度或服务商账号。

用户输入的密钥保存在本机 `data/model-config.json` 中，配置查询接口不会返回密钥。它是本地明文配置，不能上传或分享。调用 AI 时，服务端使用密钥鉴权，并将相关业务描述、表结构、样例或图片发送至用户配置的服务商。上传图片会触发识别请求，请在上传前确认材料可以发送。未配置模型时，手工建模和本地编译路径仍可使用。

项目及上传材料保存在 `data/projects/`。关闭浏览器不会删除它们。删除整个 `data/` 会同时删除所有项目和模型配置，操作前请自行备份需要的内容。备份也不能提交到公共仓库。

## 运行参数

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `PORT` | 起始端口 | `4188` |
| `STUDIO_DATA_DIR` | 项目和配置的本机保存位置 | 项目目录下的 `data/` |
| `STUDIO_HOST` | 监听地址 | `127.0.0.1` |
| `STUDIO_OPEN` | 设置为 `1` 时启动后打开浏览器 | 关闭 |

例如，macOS/Linux 可执行 `PORT=4200 node server.mjs`。这些是公开的参数定义，不含个人配置。运行数据与配置文件由使用者在本地创建，不属于仓库内容。

## 验证与打包

```sh
npm test
npm run check
npm run release:check
npm run release:zip
```

也可以直接执行 `node scripts/test.mjs`、`node check.mjs`、`node scripts/release-check.mjs` 和 `node scripts/release.mjs`。测试临时生成领域无关的虚构对象和记录，用完清理；没有独立测试数据文件。可选的外部 Excel 回归默认跳过，不要把真实文件复制进仓库。

发布脚本只收录源代码、测试和文档等白名单文件，输出 `dist/ontology-modeling-workbench-source.zip`，包含逐文件 `SHA256SUMS`。`data/`、本机配置、导出物、日志和编辑器目录不进入 ZIP。发布检查会检查候选文件及 Git 已跟踪文件；它不会扫描旧提交，规则扫描也不能替代人工保密和版权审查。

GitHub Actions 会执行单元测试、HTTP 自检和发布检查。`package.json` 保留 `private: true` 以避免误发 npm，这不影响将源码放到 GitHub 公开。
