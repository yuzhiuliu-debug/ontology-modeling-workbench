# 使用说明

## 本地启动与材料录入

执行 `node server.mjs`，打开终端打印的回环地址。首次启动没有项目和模型配置。在新项目中填写名称和本体命名空间，上传自己有权使用的材料。

- 字段字典 JSON 或 SQL 建表语句可提供结构、字段说明、主键和外键。
- Excel、CSV 可以提供表结构和用户选择的样例行；旧版二进制 `.xls` 请先转换为 `.xlsx`。
- 业务描述可补充对象含义、流程阶段和约束依据。
- 已有 OWL/Turtle 等本体文件可直接导入查看。
- 图片需要已配置且支持图片输入的模型。上传图片会把图片发送给该服务商进行识别。

数据集、规则和材料全部由使用者提供，平台没有内置业务案例。图片识别和自动推断可能出错，必须核对原文与字段映射。

## 生成理解稿与确认关系

没有模型密钥时选择手工建模，逐表填写业务含义、角色、逻辑和流程阶段。需要 AI 提案时，先在模型配置中填写服务商、HTTPS 地址、模型名和自己的密钥；自定义兼容接口需显式允许。

在草稿图谱上检查关系名称、方向、业务含义和字段依据。结构推导出的“待确认关系”需要命名或删除。整稿确认会保留已命名的候选关系，仍叫“待确认关系”的边不编译为本体关系。模型或结构建议不等于已经验证的业务事实。

确认理解稿后生成本体。可以编辑图谱、回写并导出 OWL/XML、Turtle、JSON 或图谱相关产物；请检查导出与业务意图是否一致。

## 实例与规则

需要实例时上传相应 Excel/CSV，核对表名、字段、键和跨表关联。实例检查报告用于发现待核查的数据问题，不会自动修复业务数据。

规则设立通过模型将用户输入的条款解析为结构化语义，再由程序生成 SQL。主流程不包含连接生产数据库执行这些 SQL 的能力；执行前需在外部环境评审字段、方言、口径和权限。兼容模块中保留的旧规则解释功能也不构成正式监管判定。

## 项目保存与清理

项目保存在 `data/projects/`，密钥和模型设置保存在 `data/model-config.json`；使用 `STUDIO_DATA_DIR` 可以修改保存位置。最近项目读取本机保存的项目。关闭页面或停止服务不会删除资料。

这些目录和导出文件不能上传 GitHub。删除整个 `data/` 会删除全部项目和模型配置，清理前自行确认需要保留的资料。分享源码使用发布脚本生成的 ZIP。

## 自检与排错

执行 `npm test` 和 `npm run check`。测试使用系统临时目录，不需要真实业务材料或模型账号。可选外部 Excel 回归只通过 `TEST_FIXTURE_XLSX` 指向使用者自己的文件，默认跳过。

模型报错时检查服务地址、模型名、权限及服务商支持的接口和输出预算。图片输入必须使用支持图片的模型。模型输出截断时可调整预算或拆分材料，实际限制以服务商为准。报错日志可能包含业务文本，公开提交前先脱敏。

macOS 双击脚本无执行权限时，可以在终端执行 `chmod +x 02_启动_Mac.command 04_一键自检_Mac.command`，或直接执行 Node 命令。
